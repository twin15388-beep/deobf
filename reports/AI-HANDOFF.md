## Что уже пробовали и чего не повторять вслепую

- Не применять `coazy/luraph-v14.7-unwrap` без жёсткого ограничения к обнаруженному **v14.6**: на 256 МБ он завершился **OOM**. `Melodieshusband` v14.3-десериализатор после успешного снятия оболочки отверг v14.6 VM-формат: `implausible constant count -9138 (raw=46539)`. `caomod` Luraph-детектор на *целом* Jnkie+VM-файле даёт `generic`, на выделенном Luraph-суффиксе — `v14.x` с уверенностью 0,50; это **не восстановленный исходник**.
- [`Aditya-lua/luadevirt`](https://github.com/Aditya-lua/luadevirt) на момент проверки API GitHub возвращал 404 (поисковая карточка устарела). `PumbaaDev/luau-decompiler` рассчитан на **нативный Luau bytecode**, а извлечённая стадия — байткод *другой* VM; в этой среде не было Cargo. Jnkie fetchers (`alvin12127`, `Mazsigiit`, `qopxxcrobloxscript-cyber`) используют HTTP-поставку/ключ и **не запускались**: пользователь запрещает API для получения скриптов. `0x251/Prometheus-Deobfuscator/pol.py` делает Python `eval` над входом — не запускай на непроверенном коде.
- Многоигровые хабы с кнопкой **Trident Survival/GPO** зачастую содержат лишь `HttpGet` на Luarmor; наличие `FireServer` в *другой вкладке* не доказывает восстановление этих игр. Готовый читаемый Slayers 2, MIT Aztup GPO и открытый Lone Survival не являются нашей деобфускацией. Защищённые Trident/King Legacy без подтверждённой лицензии нельзя выкладывать.
- Ранее полные PSU-выходы Zero Academia/Anime Fighters и MoonSec-выходы Item Factory/Anime Training имели неверные участки: не перепубликовывай их целиком только потому, что распаковщик завершился. Точные ограничения старых вариантов — в [protected-отчёте](game-sources-2026-10-21-protected.md). У нового Meme Adventure корень проходит `luac -p`, **но это не доказывает** эквивалентности MoonSec VM: не называй отсутствующие attack/teleport обработчики работающим AutoFarm.
- `lovesyko/SynapseXenDeobfuscator` **даже `--inspect`** после показа метаданных запускает защищённый Lua через runtime hook; для `Luciquad/bigpaintballv1` так не делать. У Trident `Edaruph/My-Scripts` нет проверенной лицензии. Не принимать `Luciquad/sl2 autofarm` за Slayers 2: код загрузчика указывает на `reavscripts/sl2-hub` для ShindoLife, и у него нет LICENSE. В MPL-репозитории neoware найден **Weak Legacy** `CustomModules/10358162137.lua` (139 022 байта, SHA-256 `9f4262ec0faa39837a1aa548d5faa522e86ab89bb8744b0ee3c5142b7224acbc`), но он защищён **77fuscator 0.5.0**, не MoonSec; сохранённый инструмент 77fuscator рассчитан на **0.6.1** и требует отсутствующего .NET SDK 8. Это **вход, не результат**. Все подробности — [отчёт](game-sources-2026-10-22-moonsec.md).

## Практический следующий шаг

1. Прочитать [../AGENTS.md](../AGENTS.md), оба последних отчёта, проверить `git status --short --branch`, `git log -1` и актуальный [PR #1](https://github.com/twin15388-beep/deobf/pull/1). Если другая AI-среда выдала *свою* ветку, следовать её правилам, а не принудительно переключаться на ветку из этой памятки.
2. Искать прежде всего **защищённое тело игры**, доступное законно, с правом на повторное распространение. Для Luarmor/Jnkie без разрешённого локального HTTP-ответа есть только loader/SDK: ни `inspect_api_delivery.py`, ни изменение URL не создадут серверный исходник. Карточки RScripts/ScriptBlox — ориентиры, GitHub-поиск — для метаданных, тела разрешённых репозиториев — через `git clone` закреплённого коммита. **Не использовать Pastefy или API для получения скриптов и не обходить ключи.**
3. Если подходящий вход найден, применять инструмент **к его реальной версии защиты**, делать статическую/изолированную проверку игровых функций и аргументов, фиксировать SHA-256 входа/выхода, лицензию, добавленные составителем изменения и честную границу полноты. Без прав или реального восстановления не создавать файл «для счётчика». При новом игровом `.lua` создать отдельный JSON-манифест, внести его в `SOURCE_REPORTS` у [`verify_results.py`](../scripts/verify_results.py), обновить каталожный README/счётчик, написать тесты и отчёт. MoonSec-ключи можно исследовать только **с ограничениями**: [`prepare_moonsec_safe_eval.py`](../scripts/prepare_moonsec_safe_eval.py) на проверенном временном клоне; это *не* общее разрешение выполнять неизвестные Lua/VM.
4. Минимум перед передачей: `python3 -m unittest discover -s tests -p 'test_*.py'` (**на этом снимке 73 теста**); `python3 scripts/verify_results.py` (**62 файла**); `python3 scripts/verify_sources.py` (**40 архивов**); `node --test tests/test_psu_fixed_calls.mjs` (**1 тест**); `git diff --check`. Отдельно для Meme Adventure при доступном Lua 5.1: `luac -p 'dobf scripts 1.0/Meme Adventure - MoonSec V3.lua'` и `lua tests/test_meme_adventure_moonsec.lua 'dobf scripts 1.0/Meme Adventure - MoonSec V3.lua'` (**10 source-only smoke**); с восемью изолированными прототипами из 11 609-байтного bytecode — **10 сравнений**. Roblox и защищённый оригинал не запускались. Если меняется игровой код, добавь профильные Lua/Luau-тесты.
5. После прохода **обновить эту памятку**: дату, фактический счётчик, новые входы/результаты/тупики, хеши и проверки. Не коммитить HAR, секреты, чужие большие защищённые образцы, сырые выгрузки, бинарники и `node_modules`.
