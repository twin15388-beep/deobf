# Деобфускация Roblox-скриптов: GPO прежде всего

18 октября 2026 г. · первая партия из **10 разных файлов**, для GPO — три образца. **Честный итог: 0 полностью восстановленных исходников; 5 частичных результатов; 5 случаев без восстановленного кода.** Ещё один файл, рекламируемый как GPO-скрипт, исследован и **исключён** из десятки: он оказался интерфейсом проверки ключа, а не заявленным автофармом.

**Открыть результаты на GitHub:** [папка `dobf scripts 1.0`](../dobf%20scripts%201.0/README.md) — в ней ссылки на каждый полученный файл с разграничением статусов.

«Частично» здесь может означать разные вещи: восстановленные функции VM, читаемые строковые константы, развёрнутый диспетчер **или только внешний контейнер**. Ничто из этого само по себе не доказывает, что результат эквивалентен исходной программе или безопасен для запуска. **Ни один Roblox/Lua-скрипт не выполнялся.**

### RScripts как указатель, не источник байтов

В карточках RScripts чаще всего размещён однострочный `loadstring(game:HttpGet(...))()`, а у некоторых карточек код отображается как **«Loading code…»**. Такой загрузчик **не засчитывался** деобфусцированным скриптом. Сами входные байты получены **только через `git` из GitHub** и закреплены коммитом/SHA-256. Для этой десятки карточки/поисковые фрагменты RScripts указывали на файлы № 2 ([карточка](https://rscripts.net/script/one-click-farm-farm-any-npc-auto-fish-and-more-qDS6)), № 4 [33](https://rscripts.net/script/best-or-aze-script-or-insane-script-or-godly-script-2YLO), № 5 [7](https://rscripts.net/script/doors-script-best-one-u1Xn), № 6 [1](https://rscripts.net/script/new-script-op-VphY) и № 7 [1](https://rscripts.net/script/arcane-odyssey-auto-fishing-6bDG). Для № 1, 3, 8–10 подтверждён лишь соответствующий файл на GitHub; привязку именно к RScripts не утверждаю. Ссылка из карточки не гарантирует неизменности содержимого GitHub `main` во времени.

## Отсеянный кандидат: рекламируется как GPO, а код — экран ключа

Карточка RScripts [1](https://rscripts.net/script/grand-piece-online-script-auto-farm-fruit-tp-vSSl) обещает GPO auto-farm и ведёт к [`dilleron964/Grand-Piece-Online.lua` на коммите `213cbab`](https://github.com/dilleron964/Grand-Piece-Online/blob/213cbab591560220ffbbc3a354de99ba3c829df7/Grand-Piece-Online.lua). Это **не один из десяти**. Скриптом `scripts/decode_lua_xor_literals.py` без исполнения Lua заменены **922/922 вызовов с двумя строковыми литералами** (153 уникальные строки); `unprom` дополнительно свернул 1 180 арифметических выражений. Результат содержит `KEY_LINK`, `VALID_KEYS`, `PhantomKeySystem` и другие элементы UI проверки ключа; GPO-автофарм, задания или фрукты в декодированном файле не обнаружены. Это свидетельствует о **несоответствии текущего файла рекламе**, но не объясняет, когда или почему возникло расхождение. Локальные результаты: `local-results/excluded-dilleron-key-ui.xor.lua` и `local-results/excluded-dilleron-key-ui.formatted.lua`. Домен из `KEY_LINK` **не открывался**.

## Как получены результаты и что осталось за рамками

- Свои маленькие офлайн-декодеры: [`decode_lua_xor_literals.py`](../scripts/decode_lua_xor_literals.py), [`unpack_luraph13_hex.py`](../scripts/unpack_luraph13_hex.py), [`unpack_luraph14_lzma.py`](../scripts/unpack_luraph14_lzma.py). Они не вызывают Lua и имеют тесты на синтетических данных: `python3 -m unittest discover -s tests -v` (**7/7**).
- Для Prometheus использованы исходники из `sources/tonybolivar--luraph-deobfuscator-updated.zip` и `sources/yennylol--unprom.zip`; их SHA-256/коммиты находятся в [`sources/manifest.json`](../sources/manifest.json). Проверялись только **статические** режимы. Python-зависимость `luaparser==4.2.0` установлена временно, за пределами репозитория. Четыре текстовых результата (№ 1, 5, 8 и отсеянный файл) прошли статический Lua-парсер; для № 4 Lua-5.1-парсер не принимает один из escape-синтаксисов Luau — это **не** проверка исполнимости.
- Для № 2, 6, 7, 9 и 10 был запущен лишь **`luauvmp inspect`**, без запуска payload: каждому вернулся отчёт «0/0 opcode slots / unresolved bytecode reader». Внешнюю Luraph v14-обёртку № 4 собственный декодер распаковал, а `luauvmp luraph` этот вариант **не** распознал.
- `dotnet`, `lua`/`luau` и Roblox-среды здесь нет. Инструменты, требующие исполнения защищённого Lua, «sandbox capture», запуска Roblox Studio или загрузки в сторонний сервис, **не запускались**. Отсутствие среды — не доказательство принципиальной невозможности деобфускации MoonSec.
- **Steal an Egg не рассматривался. Pastefy не использовался. Никаких ключей, API-доступов, RScripts raw/API или вторичных ссылок из скриптов не запрашивалось.** Входы — только публичные GitHub-репозитории по `git`; защищённый код не выполнялся. Исходные входные файлы не добавлены в Git, а производные результаты опубликованы отдельно по запросу владельца репозитория.

По запросу владельца репозитория копии производных файлов опубликованы в [`dobf scripts 1.0`](../dobf%20scripts%201.0/README.md); идентичные рабочие копии остались в `local-results/`. Файлы исходных игровых скриптов не добавлены. Лицензии/права исходных авторов на перераспространение не установлены — публичность исходника сама по себе такого разрешения не означает. Не запускайте производные `.lua/.luau`: они по-прежнему могут содержать обфусцированную логику и сетевые загрузчики.
