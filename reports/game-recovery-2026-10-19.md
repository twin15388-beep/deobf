## Процесс и воспроизведение

1. Найдены именно **обфусцированные входы**, а не открытые игровые исходники; каждый вход привязан к GitHub-репозиторию, точному коммиту, пути и SHA-256 в JSON-отчёте. Файлы `README.md` у четырёх источников содержат обфусцированный Lua непосредственно. Источники **не взяты с pastefy.app** и никакие API-доступы к скриптам не использовались.
2. Статически применён локальный снимок [prostone4/Prometheus-Deobfuscator](https://github.com/prostone4/Prometheus-Deobfuscator) `6ee3291ec83fdc58c04e17bb1f1703386619711a` (`sources/prostone4--Prometheus-Deobfuscator.zip`); [`scripts/prepare_pdeobf.py`](../scripts/prepare_pdeobf.py) проверяет хэш архива и исправляет две опечатки в парсере/проходе CFG (`BLOCK_TERMINATORS` → `TERMINATORS`, определение границ `TAIL_STATEMENTS`/`TAIL_NODES`). Проводились только чтение и преобразование исходного текста; игровая программа **не исполнялась**. В выходах остаются понятные фрагменты с вызовами игровых `Remotes`, UI, обработчиков, а не сама защитная VM.
3. Для `King Legacy`/`Illegal Soccer`: [`scripts/unflatten_game_lua.cjs`](../scripts/unflatten_game_lua.cjs) по AST разворачивает только доказуемо завершающиеся числовые диспетчеры (`28` и `19` соответственно) и однократные циклы (`19` и `24`). Для настоящих/непонятных циклов преобразование не применяется (`remainingLoops=0` в этих двух файлах относится к рассматриваемым `while true`, а не к *любым* циклам в программе). Проверено независимыми синтетическими тестами порядка ветвей.
4. Для Violence District точечный [`repair_violence_district_goto.py`](../scripts/repair_violence_district_goto.py) заменяет **только один известный шаблон** из трёх переходов к общему `return`; для WHI [`repair_wild_horse_goto.py`](../scripts/repair_wild_horse_goto.py) дублирует `task.wait()` в ветке, из которой единственный переход в неё направлен. Оба патча отказываются обрабатывать иной шаблон. Это контроль синтаксиса и локальной структуры, **не** доказательство эквивалентности целого файла.
5. Все двенадцать файлов прошли `luau-compile --null <файл>` в CLI из [Luau](https://github.com/luau-lang/luau) commit `9d7748a4f324213a18cb8283fa2a77c330225fa0`. Три частичных фрагмента прошли и `luac` Lua 5.1. Кроме того, [`verify_results.py`](../scripts/verify_results.py) сверяет inventory/размеры/SHA-256 с JSON; это также не запускает Lua.
6. **GPO (отдельный метод; только часть):** взят именно обфусцированный [`c0deblox/Scripts:GPO.lua`](https://github.com/c0deblox/Scripts/blob/472dc5871faae68dfcfbba6485a619275063ee16/GPO.lua), PSU 4.0.A (90 637 байт, SHA-256 `0f6a4be8f4477de671068d6b19977088281e9fc098a00f72b5c53bf3f0320f30`). Зафиксированный [memcpython/PSU-Deobfuscator](https://github.com/memcpython/PSU-Deobfuscator) commit `7d955d4d8e3bc14b744dc4afd52118787fc2bda4` **статически** восстановил Lua 5.1 bytecode 48 400 байт (SHA-256 `fe7dc0be0ad15266fd53765c2e53d60c4a4c61277696a93cc50cad3e06542241`), 99 прототипов, `unknownInstructions=0`. `unluac-js@1.4.4` дал 79 090 байт диагностического псевдокода **с 49 метками ошибки**, т.е. не восстановил весь хаб. `viruscamp/luadec` commit `895d923` собран против Lua 5.1; на целом файле он аварийно завершился, но частично подтвердил код квестового прототипа `0_20`. **Для публикации вручную выбраны прослеживаемые игровые участки** #9/#12 (только числовой Tween-маршрут), #11 (расстояние между точками), #17/#18 (урон), #19/#20 (поиск NPC), #22/#23 (подход над NPC), #31 (квест), #72 (бочки после исправления классификации CALL) и #90/#91 (Hie-Hie), плюс таблицы квестов/координат главного прототипа. Боевую/квестовую логику и Hie-Hie (#89 подключает `Touched`, #90/#91 содержат `Clone`, `Debris`, `Position`, `Size`, `wait`, `Destroy`) дополнительно сверили с `luac -l -l` дизассемблированием поднятого байткода. Они получили говорящие имена и модульную `return`-оболочку (не оригинальные имена/интерфейс), проверены при помощи [`test_gpo_lunar_fragment.lua`](../tests/test_gpo_lunar_fragment.lua) в изолированной подставной среде Lua 5.1. Числовые пути #9/#12 дополнительно сверены с **изолированно извлечёнными настоящими прототипами** Lua 5.1 по пяти подставным траекториям; квест #31 — по трём макетным исходам, см. [дополнение от 21 октября](game-recovery-2026-10-21.md). В [следующем проходе](game-recovery-2026-10-21-followup.md) к ним добавлены #11/#22 (расстояние и два сравнительных сценария подхода к NPC) и #72 (бочки, **три сравнения только с исправленным байткодом**, ещё два числовых маршрута с 12 аргументами и совместный прогон с #12); для #22/#72 потребовались обёртки, явно подающие один исходный upvalue. **Полная эквивалентность PSU-VM и работа в Roblox не доказаны.** Сторонние исходники инструментов без лицензии сюда не копировались.
7. **ASTD (только часть):** защищённый [`c0deblox/Scripts:ASTD.lua`](https://github.com/c0deblox/Scripts/blob/472dc5871faae68dfcfbba6485a619275063ee16/ASTD.lua) 89 862 байта, SHA-256 `0d7df2741df21fce25990d7b30fe7128d7b43d8d71b37a3d60d5442439e56564`. Псевдокод `unluac-js@1.4.4` содержит **46 ошибок**, поэтому выбранные игровые действия #18, #19/#21, #22, #23 сверены с **дизассемблированными инструкциями и константами** `SellAtWave`/`Sell`, `Summon`, `Upgrade`, `VoteWaveConfirm`. Воспроизведение для отдельного входа, где `REPO`, `COMMIT`, `PATH` берутся **без изменений** из `game-recovery-2026-10-19.json`:

```bash
# Используйте свою временную директорию; показан пример для Pantheon JJS.
git clone --no-checkout https://github.com/pantheon111/jjs.git /tmp/jjs-recovery
# Если коммита ещё нет в локальном клоне: git -C /tmp/jjs-recovery fetch origin a5c3df2b86bc119e747a2e47374a6e7f17ad9371
git -C /tmp/jjs-recovery show a5c3df2b86bc119e747a2e47374a6e7f17ad9371:jujutsu_shenanigans_obfuscated.lua > /tmp/input.lua
PDEOBF_ROOT=$(python3 scripts/prepare_pdeobf.py)
node "$PDEOBF_ROOT/bin/pdeobf.js" /tmp/input.lua -o /tmp/result.lua
python3 scripts/verify_results.py
```

Для остальных **восьми прежних** файлов использован тот же `node "$PDEOBF_ROOT/bin/pdeobf.js" in.lua -o out.lua`, после чего для **двух** расплющенных файлов:

```bash
node scripts/unflatten_game_lua.cjs "$PDEOBF_ROOT" out.lua structured.lua
```

Для Violence District/WHI применяется соответствующий `python3 scripts/repair_*_goto.py out.lua structured.lua`; не запускайте неизвестный Roblox-скрипт, чтобы воспроизвести статический вывод. Для локальных тестов: `python3 -m unittest discover -s tests` и `PDEOBF_ROOT=$(python3 scripts/prepare_pdeobf.py) node --test tests/test_unflatten_game_lua.cjs`.

**PSU — отдельное воспроизведение без исполнения защищённого Lua:** клонировать `c0deblox/Scripts` и `memcpython/PSU-Deobfuscator` по коммитам из JSON, прочитать `git show 472dc587:GPO.lua` (или `:ASTD.lua` / `:Ro-Ghoul.lua`) в отдельный `/tmp/psu-input.lua`. В каталоге PSU выполнить `npm ci --ignore-scripts` и `node src/cli.js /tmp/psu-input.lua --check --bytecode /tmp/psu.luac --json`; проверить SHA-256 байткода соответствующего случая из JSON и дизассемблировать `luac -l -l /tmp/psu.luac` Lua 5.1. Частичные опубликованные файлы **не автоматически пересоздаются**: выбор функций, переименования и явные параметры сделаны вручную. Дополнительный `scripts/extract_lua51_prototype.py` выделяет только самостоятельные прототипы из поднятого байткода; инструкции и безопасный макет для GPO — [в новом отчёте](game-recovery-2026-10-21.md). Каждый файл отдельно проверяется `luau-compile --null '<имя-файла>.lua'`, `luac -p -o /tmp/check.luac '<имя-файла>.lua'` и подходящим Lua 5.1 тестом из `tests/test_{gpo_lunar,astd,roghoul}_fragment.lua` (подставить фактический путь к файлу, названия компиляторов зависят от сборки).

## Ограничения, отказы и отрицательные проверки

- **Другие GPO-входы не восстановлены или отклонены.** У `0xRinFin/GPO` и `AdelOnTheTop/Adel-Hub` входы под Luraph v13.x: источники v14.x/v15.x в коллекции нельзя выдавать за декомпилятор v13. `CFA-HUB/CFAHub-Free:SeaHubCrackGPO.lua` статическим PSU-лифтером поднят в Lua 5.1 bytecode (`unknownInstructions=0`) и `unluac-js@1.4.4` вернул компилируемый фрагмент; сравнение с читаемым GPO-файлом из того же репозитория подтверждает игровой remote `Events.CIcklcon`, но содержимое ограничено выстрелами Rifle и общим noclip, а не логикой целого GPO-хаба. XOR-декодирование файла `dilleron964/Grand-Piece-Online` выявило лишь PHANTOM key UI. Эти файлы не опубликованы. Другие открытые GPO-исходники уже читались без деобфускации и также не выдаются за результат.
- **Blox Fruits:** PSU-лифтер поднял байткод, но `unluac-js` вернул `diagnostic-pseudocode`/`unresolved HIR expression: open-pack`; Lua-кода для публикации нет. `pdeobf --force` на других PSU/Boronide-входах оставлял VM, поэтому его принудительный вывод не используется.
- **Case Paradise:** у MoonVeil v1.4.5 `--no-verify` вывел компилируемый текст, но проверка выявила присваивание `true` в ветке для `false` и обращение `.Panel` к `false`: это сломанная реконструкция. **Night** содержит только ключевой интерфейс и внешний загрузчик, не обработчики игры; **Ride a Pet** вход заканчивается посреди выражения; **Grow a Garden** дал только загрузчик удалённого кода с параметром webhook, без локальной игровой логики. Они не публикуются. Аналогично отброшен GUI-лоадер из `Obfuscado-big-bang` и общий скрипт сиденья/телепортации из `script-fuga`.
- `AnnonyA/WAD-deobf` на части игровых WAD сообщил `valid WAD alphabet not found` / `WAD VM dispatcher not found`; `yennylol/unprom` на большом входе — `RecursionError`. Эти ошибки не приравнены к полному восстановлению.
- King Legacy `core.lua` — **промежуточный** результат: брендированный UI, ESP и отображение PvP/уровня, но ESP и выбор игрока могут быть применимы к нескольким играм. Он намеренно не называется специфичным фармом King Legacy. В Illegal Soccer остаётся присваивание `v220` без объявления `local`. В Pantheon остаются неразрешённые глобалы; у других выходов остаются внешние UI-загрузки. Все эти файлы требуют независимого аудита перед использованием.
- Публичность GitHub-репозитория **не означает свободную лицензию**: в девяти прежних исходных снимках не обнаружен `LICENSE`; права на три дополнительно обработанных входа из `c0deblox/Scripts` также не подтверждены. Атрибуция, полный URL и коммиты приведены в JSON; права на повторную публикацию необходимо проверять отдельно.

**Проверено только:** наличие вывода, снятие соответствующей защитной оболочки, понятность конкретных фрагментов и компиляция. **Не проверено:** запуск в Roblox, актуальность ремоутов и объектов, эквивалентность исходному защищённому сценарию, безопасность внешних ссылок.
