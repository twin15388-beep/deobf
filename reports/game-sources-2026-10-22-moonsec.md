## Как снята защита — и граница доказательства

1. [`luaprojects/moonsec-js-deobf@7a4be808`](https://github.com/luaprojects/moonsec-js-deobf/tree/7a4be80850f2b2a5ad20a02ef486d518f2164b27) — JS-порт MoonSec V3-девиртуализатора (инструмент заявляет GPL-3.0; код **не копировался** в этот репозиторий). Перед запуском [`scripts/prepare_moonsec_safe_eval.py`](../scripts/prepare_moonsec_safe_eval.py) сверил коммит и SHA исходника инструмента, отключил *все* стандартные библиотеки Fengari Lua и ограничил вычисляемые выражения ключей локальными числовыми временными переменными/арифметикой/ветвлением. Проверенный ключевой фрагмент здесь: без строк, имён внешних функций и доступа к `os`, `io`, `require` или Roblox. `npm ci --ignore-scripts`, пустое окружение с минимальным PATH, ограничение Node **256 MiB**; защищённый top-level/VM **не исполнялся**. Это ограничение подходит не любому MoonSec-входу: неожиданный ключ безопасно отвергается.
2. Результат девиртуализации — **11 609 байт Lua 5.1 bytecode**, SHA-256 `2df2d2acc40f972c98d1128201ccbddeff3bdd32a026c3ef4a827c9e80fae8d6`; в отличие от Item Factory, **корень проходит `luac -p`**. Парсер видит **29 прототипов** (24 прямых дочерних, пять вложенных). Bytecode — промежуточная стадия **вне Git**, не выдаётся за исходник.
3. `unluac-js@1.4.4` (`decompileRich`/`lua5.1`) через [`scripts/decompile_lua51.mjs`](../scripts/decompile_lua51.mjs) выдал полностью читаемое 315-строчное тело. Оно проходит **Lua 5.1 `luac -p`**. Вторые независимые запуски *того же* инструментального пути дали побайтово тот же bytecode и то же тело. Это воспроизводимость декодера, **не** сравнение с авторским незащищённым исходником.
4. **Десять** случаев сопоставляют побочные эффекты выбранных **изолированных** распакованных прототипов и точно выделенных из опубликованного тела callbacks на макетах: `0_3`, `0_4`, `0_10`, `0_16`, `0_21` (два значения), `0_8_0_0`, `0_8_1_0`, `0_0` (две точки). Для последнего `extract_lua51_prototype.py --wrap-upvalues` создаёт только синтетического родителя с явными upvalue. Глобалы ограничены макетами без `io/os/require/HttpGet`; Lua debug hook ограничивает число инструкций. **Полный восстановленный корень также не выполнялся**. Сверка выбранных детей не доказывает эквивалентность всех 29 прототипов оригинальной MoonSec VM или безопасность чужой UI/реальных серверов.

| Оружие | Разовый сбор названий `Tool` из `LocalPlayer.Backpack`, dropdown и цикл при флаге `r0_18`: каждые **0,1 с** `Backpack:FindFirstChild(выбранное имя)` → `Character.Humanoid:EquipTool(tool)`. ## Повторение и текущие отрицательные находки

Офлайн-рецепт (временные каталоги **вне Git**): `git clone` двух указанных закреплённых репозиториев; для MoonSec-инструмента подтвердить `git rev-parse HEAD == 7a4be80850f2b2a5ad20a02ef486d518f2164b27`, выполнить `npm ci --ignore-scripts --no-audit --no-fund` и `python3 scripts/prepare_moonsec_safe_eval.py /tmp/<tool>`. Затем **с ограничением времени** вызвать `env -i PATH=/usr/local/bin:/usr/bin:/bin HOME=/tmp node --max-old-space-size=256 /tmp/<tool>/bin/moonsec.js -dev -i /tmp/<input>/CustomModules/9566949295.lua -o /tmp/meme.luac`; сверить SHA bytecode выше. В отдельной временной папке установить `unluac-js@1.4.4` через `npm install --prefix /tmp/<decompiler> --no-save --ignore-scripts`, туда же положить копию `scripts/decompile_lua51.mjs`, выполнить `node /tmp/<decompiler>/decompile_lua51.mjs /tmp/meme.luac /tmp/meme.lua`; сверить SHA тела выше. Lua 5.1 для `luac -p` в этом sandbox собран во временный каталог из [`LuaDist/lua@d2e7e7d`](https://github.com/LuaDist/lua/tree/d2e7e7d4d43ff9068b279a617c5b2ca2c2771676) (из-за mirror-файла `luaconf.h.orig` он скопирован в `src/luaconf.h` перед `make generic`).
