# BloxStrike «Symbiote» — что это на самом деле (25 октября 2026)

**Ветка:** `arena/2cc60032-deobf`. **Итог прохода:** защищённый вход разобран и его поведение
восстановлено, но **игрового кода в нём нет** — это **Symbiote Key System**, ключевой шлюз
(UI + проверка ключа), который загружает настоящую игровую логику с сервера. Поэтому в
каталог [`dobf scripts 1.0/`](../dobf%20scripts%201.0/README.md) ничего не добавлено,
счётчик остаётся **67 = 32 + 35 `(src)`**, новых `(src)` тоже нет.

## Метод (офлайн, без сети и без обхода авторизации)

1. Загрузчик вставлен в файл-хост и запущен в песочнице **Luau 0.739** (`local-results/_tools/luau-0.739`,
   сборка из `scripts/prepare_luau.py`). `loadstring`/`load` подменены на регистратор: получили
   распакованный внутренний чанк **165 203 байта** (`stage2.lua`,
   SHA-256 `ea520ea3c3f35513a2930dedad8548785d97d6844baafa898813fe1be7a5231d`).
2. Этот чанк — `return function(ja, ...) return({function(j) … end, …}):l({…96 строковых ключей…}, "L", …) end`:
   VM с плоским диспетчером по `i`-состоянию, MBA-арифметикой, кэшем констант `j.G[idx]` и двумя
   ASCII85-подобными блоками, которые он сам декодирует.
3. Дальше — **не девиртуализация, а трассировка поведения**: записывающие заглушки всех Roblox-глобалов
   (`Instance`, `Color3`, `UDim2`, `TweenInfo`, `Enum`, `game`, сервисы, `request`, `setclipboard`,
   `task`, `loadstring`), регистратор `Text`/`Name` у объектов, перехват `Connect` и точечный вызов
   **одного** колбэка за прогон, собственный JSON-декодер для `HttpService:JSONDecode`,
   собственный JSON-энкодер для `JSONEncode`, проксирование декодированного ответа, чтобы видеть,
   какие поля payload читает.
4. Восемь сценариев (пустой ключ, отказ сервера, отсутствие полей, подпись, падение основного хоста,
   «Get Key» с ответом и без) прогнаны **дважды**: по защищённому payload и по нашей реконструкции;
   результаты сравнены автоматически.

Скрипты и артефакты лежат в игнорируемом `local-results/work_bloxstrike/` (`gen_final.py`,
`gen_variant.py`, `verify_matrix.py`, `compare_traces.py`, `final_trace.txt`, `reconstructed_keysystem.lua`),
в Git они не попадают: это третья сторона без подтверждённых прав.

## Что делает payload: **Symbiote Key System**

Корневой объект — `ScreenGui` с именем `KeySystemGui` (`DisplayOrder = 999`, `IgnoreGuiInset`,
`ResetOnSpawn = false`, `ZIndexBehavior = Sibling`), который перед созданием уничтожает одноимённый
существующий. Внутри: затемнение 1×1 (`BackgroundTransparency = 0.5`), карточка `Card` **460×310**
по центру, верхняя панель `TopBar` высотой **42**, содержимое `Content` (1,−40 / 1,−64) и
полоса прогресса `(1,0,0,2)` внизу с `UIGradient`.

Заголовок: `◆` + `"  Symbiote Key System "`, кнопка закрытия `Close` (30×30, `X`).
Подсказка: `"Enter your key below to continue. If you don't have one, click 'Get Key'."`
Поле ввода — `TextBox` с `PlaceholderText = "Paste key here..."`, шрифт `Code`, `ClearTextOnFocus = false`,
под ним рамка `UIStroke`, меняющая цвет на `Focused`/`FocusLost`. Кнопки: `Get Key`
(0.35,−4 × 42) и `Continue` (0.65,−4 × 42), ссылка
`"Join Discord: https://discord.gg/9QAWtYxbcb"` (копируется в буфер обмена по клику, если есть `setclipboard`).
Палитра — 22 значения `Color3.fromRGB` (тёмно-фиолетовая база `8,6,14`…`32,26,52`, акценты `140,60,255`
и `170,100,255`, текст `245,240,255`, успех `80,220,150`, ошибка `240,65,75`, золото `250,204,21`).

### «Get Key»

`GET https://symbiote.cc/getlink`, заголовок `Content-Type: application/json`, тела и `X-Payload` нет.
Ответ `JSONDecode(...).url` (поле именно `url`; `link` и `data.url` игнорируются) копируется
`setclipboard`, кнопка показывает `Copied!` и возвращается к `Get Key`. При сетевой ошибке —
**ровно один** повтор на `https://symbiote.up.railway.app/getlink`. Ключ в этом пути не участвует:
четыре разных значения в поле дали побайтово одинаковую трассу.

### «Continue» — проверка ключа

1. Ключ читается из `TextBox.Text`; **пустая строка → выхода нет вообще**: запроса не будет,
   сообщения об ошибке тоже (проверено сценарием `empty-key`).
2. Кнопка гаснет (`Active = false`, текст → `Verifying...` через tween 0.1 c, `Quart`/`Out`),
   полоса прогресса проявляется.
3. Собирается `{ platform, key, clientId, userId, executor }`:
   `UserInputService:GetPlatform()`, `key`, `game:GetService("RbxAnalyticsService"):GetClientId()`,
   `Players.LocalPlayer.UserId`, `identifyexecutor()` — и уходит **`JSONEncode`**.
4. Запрос: **`GET https://symbiote.cc/getloader`** с заголовками
   `Content-Type: application/json` и **`X-Payload: base64url(JSON)`** (без padding).
   Метод именно GET, тело не используется — данные проверки лежат в заголовке.
   При ошибке/`StatusCode ≥ 400`/`Success == false` — один повтор на
   `https://symbiote.up.railway.app/getloader` с тем же `X-Payload`.
5. Ответ читается как `success`, `expires_at`, `loader`, `loader_sig`, `session_token`
   (последние два — опционально). При `success ~= true` форма **молча** возвращается в исходное
   состояние: ни тоста, ни текста ошибки, ни загрузки.
6. При успехе строится тост `KeyExpiryToast` (`ScreenGui`, `DisplayOrder = 9999`, 320×72 справа
   снизу, зелёная полоса `UIStroke`/`UICorner`, `"◆  Key Active"` и
   `"Key will expire in:  " .. <форматтер>`), он выезжает (0.4 c), ждёт и уезжает (0.35 c) и
   `Destroy()`.
7. **`loadstring(loader, "Load")`** — серверный чанк исполняется в текущем окружении
   (перехвачено: `CHUNK 2 len=98`, имя чанка `Load`). Затем карточка схлопывается по высоте
   (0.25 c), затемнение исчезает, `KeySystemGui:Destroy()`, игра продолжается.
8. **Подпись loader'а.** Если в ответе есть `loader_sig`, оригинал читает его трижды и
   **не исполняет** `loader` при несовпадении: GUI остаётся, кнопка возвращается к `Continue`.
   Ни один из подставных вариантов (`md5`/`sha1`/`sha256` в hex/base64, CRC32, длина, сумма байт,
   hex разной длины) не подошёл — алгоритм проверки неизвестен (см. «Ограничения»). Без `loader_sig`
   `loader` исполняется без проверки. То есть реальный игровой код всегда приходит с сервера и
   подписан; локально его нет.

## Сценарии и наблюдаемые результаты

| Сценарий | Запросы | Тост | `loader` исполнен |
| --- | --- | --- | --- |
| ключ + `success:true`, есть `loader` | 1× `getloader` | да | да (`loadstring`) |
| пустой ключ | нет | нет | нет |
| `success:false` | 1× `getloader` | нет | нет |
| `success:true`, без `loader` | 1× `getloader` | да | нет |
| `success:true`, `loader` + `loader_sig` | 1× `getloader` | да | **нет** (подпись отвергнута) |
| основной хост недоступен | `getloader` → `up.railway.app/getloader` | да | да |

| «Get Key», основной хост недоступен | `getlink` → `up.railway.app/getlink` | — | `setclipboard(url)` |

## Ограничения и что не восстановлено

- **Внутренняя VM не девиртуализирована.** 165 203-байтный чанк — плоский `while true do if i<…`
  диспетчер с MBA; ручного восстановления по инструкциям не делалось. Всё выше — наблюдаемое
  поведение, а не разобранный байткод.
- **Игровой логики в файле нет.** Она приходит в поле `loader` после проверки ключа; серверный ответ
  мы не запрашивали (обход ключа/авторизации запрещён), поэтому игровые функции, обработчики и
  параметры **отсутствуют** — публиковать нечего.
- **Формат `expires_at`** раскрыт не полностью: оригинал читает поле, но в песочнице всегда печатает
  `Key will expire in:  Unknown` при любом значении (число/строка/ISO), а строка вызывает ошибку —
  значит внутри есть арифметика и внешняя зависимость, которую мы не воспроизвели. `os.date`/`os.time`/
  `tick`/`DateTime` при этом не вызываются вовсе.
- **Алгоритм `loader_sig`** неизвестен: проверка целиком внутри VM (без обращений к глобалам), ни один
  стандартный хеш от источника не подошёл. Само наличие проверки подтверждено поведением.
- Оформление (точные цвета градиентов, радиусы, часть `UIStroke`) восстановлено частично; имена
  внутренних переменных, структура функций и палитра-таблица — работа составителя.
- `platform` в оригинале попадает в JSON как `"Sandbox"` (из `GetPlatform()`, у нас — таблица с
  `Name`), `userId`/`clientId` в песочнице подставные; реальные значения не проверялись.
- Roblox не запускался: среда — Luau CLI с заглушками.

## Права

Лицензия и разрешение на перераспространение у входа **не подтверждены** (сторонний файл с каталога
скриптов). Поэтому: в каталог и в Git не добавлены ни защищённый чанк, ни реконструкция, ни трассы;
колбэки/эндпоинты и короткие строки интерфейса приведены только как результат анализа. Если владелец
каталога подтвердит права, реконструкцию можно оформить как `loader_only`/UI-артефакт — но это
по-прежнему не игровой результат.

## Тупики этого прохода (не повторять вслепую)

- Офлайн-декодирование двух ASCII85-подобных блоков невозможно: алфавит не совпадает со стандартным
  ASCII85, а сами блоки декодируются VM уже во время исполнения.
- Подмена `table.concat`/`string.char` для вытаскивания строк даёт только фрагменты собственного
  декодера VM (`"ret"`, `"urn "`), а не текст payload'а.
- `table.concat`/`string.unpack`-счётчики (`unpack` ×44 834, 44 031 слово, 2,7 ГБ просканировано)
  полезны только как оценка размера, не как восстановление.
- Подбор `loader_sig` перебором стандартных хешей — 9 вариантов, все отвергнуты.
- Инструментарий: в этой среде доступны только Python/JS/Lua/Luau; C#/Java/Cargo-декомпиляторы
  по-прежнему недоступны, а для частной VM их и нет.
