# Три игровых результата из защищённых входов — 21 октября 2026

**Добавлены именно восстановленные игровые Lua, не `(src)` и не однострочные loader-ы:** частичный Zero Academia (восемь выбранных обработчиков PSU), статически раскрытый Fight Your Zombie (всё тело выхода WAD-декодера) и частичный Item Factory (десять выбранных MoonSec V3-прототипов с игровой логикой). Теперь в `dobf scripts 1.0` **60 Lua: 25 восстановлений, включая частичные, и 35 ранее добавленных `(src)`**. Входы взяты из закреплённых коммитов GitHub, а не из Pastefy/API для получения скриптов. [Манифест с SHA-256](game-sources-2026-10-21-protected.json) · [каталог файлов](../dobf%20scripts%201.0/README.md).

> **Предел проверки:** ни оригинальные защищённые top-level, ни выходы не запускались в Roblox. Lua 5.1/Luau-компиляция доказывает синтаксис, не работоспособность, безопасность или семантическую эквивалентность. Для Zero Academia проведено сравнение на макетах *только с восемью выделенными дочерними прототипами исправленного подъёма PSU*, а не с работающим исходным хабом. ## Zero Academia — ZeroScripts `(partial)`

- **Файл:** [`Zero Academia - ZeroScripts (partial).lua`](../dobf%20scripts%201.0/Zero%20Academia%20-%20ZeroScripts%20%28partial%29.lua), 11 691 байт; **240 строк тела** включая пояснения составителя. Исходный [защищённый `ZeroScripts/ZeroAcademia/Script.lua`](https://github.com/teppyboy/RbxScripts/blob/58a52a25dde88cd939d679ed74dc63542a2cacd2/ZeroScripts/ZeroAcademia/Script.lua) — 64 070 байт, SHA-256 `0630d5d1c34ffe0ee1604c49cbc8c0dce83233cf638fb5b49a11f60fb309b4ad`; корневая MIT-лицензия дословно вставлена в заголовок результата. **Не** полное раскрытие этого скрипта.
- Инструмент `memcpython/PSU-Deobfuscator` поднял Lua 5.1-байткод с 0 неизвестных инструкций. Наш [`scripts/lift_psu_multireturn.mjs`](../scripts/lift_psu_multireturn.mjs) исправил **21** инструкцию CALL с многоаргументным/многорезультатным значением; до исправления прототипы давали неверное поведение. Полные `unluac-js`/Java-выводы остались некорректными (включая неверные `goto` и вызовы), поэтому **не** публикуются. Через [`scripts/extract_lua51_prototype.py`](../scripts/extract_lua51_prototype.py) из *исправленного* лифта изолированы ровно восемь нужных дочерних прототипов.
- В опубликованном модуле эти восемь обработчиков **переписаны вручную**: `questSnapshot(player)` извлекает Name/Progress/Target из папки задания; `autoQuestLoop(state,deps)` отправляет `CancelQuest`, `AcceptQuest(QuestName)`, `CompleteQuest(quest.Name)` и обновляет две UI-метки. Для старого задания с другим именем цикл всё ещё показывает старые данные — оставлено поведение выделенного прототипа, а не исправлено «как должно быть».
- `npcAlive(npc)` проверяет Humanoid, HumanoidRootPart и здоровье `> 0`; `tweenToNpc(npc,settings,deps)` использует смещение `settings.Vector3`, скорость **150 studs/s**, дополнительный вертикальный Tween при `dy > 5` и поворот `settings.Rotation` в градусах; `pressKey(key,argument,deps)` шлёт `workspace[player.Name][quirk][key]:FireServer([argument])` только при `playerReady` и `keyAvailable(key)`; `swing(argument,deps)` аналогично работает с `workspace[player.Name].Main.Swing` при `swingAvailable()`.
- `autoFarm(state,deps)` берёт `state.AutoFarm = {NameVerified, NPCs, Retries, Enabled}` и `state.Keys` из записей `{key, enabled, argumentType, mode}` с `mode == "AutoFarm++"`. Проверяет имена NPC с числом повторов, привязывает RenderStep `hoax`, выбирает NPC, зовёт внешние `deps.getNPC`, `deps.npcValid`, `deps.tweenToModel`, `deps.useKey` с CFrame/Vector3 по типу клавиши. В файле **нет** реализации `getNPC`/`useKey`, проверки имён, UI bootstrap или обработки respawn; обработчик отдельно не является работающим автофармом. Ошибка в середине цикла может оставить RenderStep привязанным.
- `autoSpinLoop(state,deps)` при `Cash.Value > 5000` шлёт `Remotes.Spin:FireServer("CommonSpin")` и сверяет выпавший quirk с `state.QuirkSpin.QuirkNames`/`IDs` без ограничения ожидания его изменения. **Может тратить игровую валюту и застрять в ожидании.** Внешние getPlayerStats/getQuirk/split и UI-метка обязательны.

**Происхождение дополнительных строк:** названия функций, таблица `return`, явные `state`/`deps` и англоязычные пояснения **написаны при реконструкции**, а не вычитаны буквально из исходника. Хеш тела относится к *нашему частичному модулю*; это не «восстановлено 64 КБ оригинала». Тест [`tests/test_zero_academia_partial.lua`](../tests/test_zero_academia_partial.lua) выполнил **28 сценариев** на mock-объектах (квесты 5, NPC 5, движение 2, бой 8, спины 4, фарм 4) как с модулем, так и с выделенными прототипами исправленного bytecode. Защищённый top-level не исполнялся. Без переданного каталога прототипов тест запускает только mock-smoke; сами `.luac` не добавлены в Git и их нужно снова извлекать из указанного защищённого входа. Дополнительно прошли `luac -p` Lua 5.1 и `luau-compile --null`.

- **Не один UI:** `f5()` ищет `workspace.Debris.Normal.Main`/ProximityPrompt (Lucky Block); `f6()` выбирает ближайший `Plots[*].PlotContents.TreeSpawn`; `f7()` — ближайшего `WalkingZombies[*].RootPart`. Рабочие циклы раз в **0,1/0,01/0,1 с** перемещают персонажа к блоку, зомби или спавну дерева в порядке приоритета. `KillAura` раз в **0,1 с** читает ID из `SelectedAxe` и вызывает `ReplicatedStorage.Remotes.EquipAxe:FireServer(id)` и `AxeSwing:FireServer()`; `AutoCollectCoin` изменяет размер `workspace.Orbs[*].Coin.HitBox` на `50×50×50`. - Ограничения/эффекты: при включении Plot Farm обработчик UI **обнуляет Health для записи точки respawn**; загрузка сохранённого конфига может сразу активировать циклы. Флаги сбрасываются, когда цель исчезает *при включённом* тумблере. Необязательные `isfile`/`writefile` сохраняют `MoMoHub_Data/Settings.json`, анти-AFK использует VirtualUser, кнопка может скопировать Discord-инвайт. **При старте выполняется `loadstring(game:HttpGet(...Framework.luau))()` из изменяемого GitHub-репозитория X2ZU**: это только внешняя UI-библиотека (игровые функции есть в данном файле), она **не включена, не проверена и не гарантирована доступной**. Отказ публиковать сомнительные выходы лучше файла с неверным именем или однострочного загрузчика.

Проверка целостности без запуска игрового Lua: `python3 scripts/verify_results.py` (целостность и ярлыки), `python3 scripts/verify_sources.py`; для синтаксиса **три** новых Lua — `luac -p` (версия 5.1) и `luau-compile --null`. Отдельно *восстановленный* MoMoHub проверен без сети/Roblox: `lua5.1 tests/test_fight_your_zombie.lua 'dobf scripts 1.0/Fight Your Zombie - MoMoHub.lua'`. Этот mock-тест не исполняет защищённый README или внешний UI и не проверяет реальные серверные ответы.
