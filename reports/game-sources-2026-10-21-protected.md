- Инструмент `memcpython/PSU-Deobfuscator` поднял Lua 5.1-байткод с 0 неизвестных инструкций. Наш [`scripts/lift_psu_multireturn.mjs`](../scripts/lift_psu_multireturn.mjs) исправил **21** инструкцию CALL с многоаргументным/многорезультатным значением; до исправления прототипы давали неверное поведение. Полные `unluac-js`/Java-выводы остались некорректными (включая неверные `goto` и вызовы), поэтому **не** публикуются. Через [`scripts/extract_lua51_prototype.py`](../scripts/extract_lua51_prototype.py) из *исправленного* лифта изолированы ровно восемь нужных дочерних прототипов.
- В опубликованном модуле эти восемь обработчиков **переписаны вручную**: `questSnapshot(player)` извлекает Name/Progress/Target из папки задания; `autoQuestLoop(state,deps)` отправляет `CancelQuest`, `AcceptQuest(QuestName)`, `CompleteQuest(quest.Name)` и обновляет две UI-метки. Для старого задания с другим именем цикл всё ещё показывает старые данные — оставлено поведение выделенного прототипа, а не исправлено «как должно быть».
- `npcAlive(npc)` проверяет Humanoid, HumanoidRootPart и здоровье `> 0`; `tweenToNpc(npc,settings,deps)` использует смещение `settings.Vector3`, скорость **150 studs/s**, дополнительный вертикальный Tween при `dy > 5` и поворот `settings.Rotation` в градусах; `pressKey(key,argument,deps)` шлёт `workspace[player.Name][quirk][key]:FireServer([argument])` только при `playerReady` и `keyAvailable(key)`; `swing(argument,deps)` аналогично работает с `workspace[player.Name].Main.Swing` при `swingAvailable()`.
- `autoFarm(state,deps)` берёт `state.AutoFarm = {NameVerified, NPCs, Retries, Enabled}` и `state.Keys` из записей `{key, enabled, argumentType, mode}` с `mode == "AutoFarm++"`. Проверяет имена NPC с числом повторов, привязывает RenderStep `hoax`, выбирает NPC, зовёт внешние `deps.getNPC`, `deps.npcValid`, `deps.tweenToModel`, `deps.useKey` с CFrame/Vector3 по типу клавиши. В файле **нет** реализации `getNPC`/`useKey`, проверки имён, UI bootstrap или обработки respawn; обработчик отдельно не является работающим автофармом. Ошибка в середине цикла может оставить RenderStep привязанным.
- `autoSpinLoop(state,deps)` при `Cash.Value > 5000` шлёт `Remotes.Spin:FireServer("CommonSpin")` и сверяет выпавший quirk с `state.QuirkSpin.QuirkNames`/`IDs` без ограничения ожидания его изменения. **Может тратить игровую валюту и застрять в ожидании.** Внешние getPlayerStats/getQuirk/split и UI-метка обязательны.

**Происхождение дополнительных строк:** названия функций, таблица `return`, явные `state`/`deps` и англоязычные пояснения **написаны при реконструкции**, а не вычитаны буквально из исходника. Хеш тела относится к *нашему частичному модулю*; это не «восстановлено 64 КБ оригинала». Тест [`tests/test_zero_academia_partial.lua`](../tests/test_zero_academia_partial.lua) выполнил **28 сценариев** на mock-объектах (квесты 5, NPC 5, движение 2, бой 8, спины 4, фарм 4) как с модулем, так и с выделенными прототипами исправленного bytecode. Защищённый top-level не исполнялся. Без переданного каталога прототипов тест запускает только mock-smoke; сами `.luac` не добавлены в Git и их нужно снова извлекать из указанного защищённого входа.
