# Инструкции для следующего кодового ИИ

Этот файл — **правила работы с репозиторием**, а не веса или настройки конкретной нейросети. Перед началом прочитай [текущую передачу контекста](reports/AI-HANDOFF.md), [README](README.md) и отчёт о [последнем проходе Luarmor/Jnkie](reports/offline-luarmor-jnkie-2026-10-22.md). Состояние и хеши в передаче — снимок на указанную дату: сначала проверь `git status`, HEAD и открытый PR.

## Задача и граница результата

- Цель пользователя — **содержательные игровые Roblox Lua/Luau, раскрытые из защищённых входов**. Приоритет: Lone Survival, Trident Survival, Slayers 2, Grand Piece Online (GPO), King Legacy; допустимы другие конкретно названные RPG/игры и несколько вариантов на игру. **Steal an Egg не обрабатывать.**
- Сейчас **не добавляй новые `(src)`**: уже открытый исходник не является деобфускацией. Не добавляй универсальный скрипт, UI, SDK, loader, удалённую ссылку, большой непрочитанный шифротекст или бинарный VM-дамп под видом игрового результата.
- Различай `deobfuscated` (восстановленные игровые функции), `(partial)` (только точно указанные фрагменты), существующие `(src)` (открытый исходник), `loader_only`/`sdk_only`/`protected_payload` (не результат), неудачу и неподтверждённое поведение. Компиляция и тест с подставными объектами **не доказывают** работу в Roblox или эквивалентность всей защищённой VM.
- Для каждого опубликованного файла укажи игру, конкретные обработчики, назначения **и параметры**, полноту, внешние зависимости/опасные действия (трата валюты, удаление предметов, телеметрия), метод восстановления, контрольные хеши и честные ограничения. Считай объём игрового кода отдельно от UI.
- Объяснения по-русски, добавленные имена, `state`/`deps`, параметры и оболочки ручной реконструкции маркируй **как работу составителя**, не как дословные комментарии автора. Не выдавай чужой готовый «deobfuscated» файл за наш вывод без проверяемой пары вход → результат.

## Доступ, права и безопасность

- **Не брать код с `https://pastefy.app`; не использовать API для получения скриптов.** GitHub API допустим для *метаданных* поиска/PR, но тело входа получать из разрешённого локального файла или через обычный `git clone` закреплённого публичного репозитория. Карточки RScripts/ScriptBlox можно просматривать, но описание фич не заменяет тело скрипта и права на публикацию.
- Не подбирать и не просить ключи, HWID, токены, HAR или учётные данные; не обходить авторизацию Luarmor/Jnkie. Если серверный payload не предоставлен законно как локальный вход, прямо напиши, что его нет. Не запускай незнакомый защищённый Lua, сетевые fetchers или Python `eval` над входом. Офлайн-распаковка оболочки **не** означает деобфускацию VM.
- Проверь **лицензию именно публикуемого скрипта**, происхождение, закреплённый коммит и право на перераспространение. MIT/GPL у *инструмента* или коллекции сами по себе не разрешают выкладывать содержащийся там игровой образец третьей стороны. Нелицензированные входы можно исследовать локально, но не копировать в каталог или отчёт большими фрагментами.
- Сырые образцы, выгрузки, HAR и полученный байткод держи вне Git или под игнорируемым `local-results/`/`captures/` (см. [.gitignore](.gitignore)). Перед коммитом проверь `git diff --cached --stat` и отсутствие секретов. Не меняй существующие игровые файлы/манифесты без причины.

## Воспроизводимый рабочий цикл

1. Уточни текущую ветку и требования среды: `git status --short --branch && git log -1 --oneline`. В этой Arena-сессии рабочая ветка фиксирована: `arena/23a8e665-deobf`, PR [#1](https://github.com/twin15388-beep/deobf/pull/1). **Не переключай, не создавай и не пушь другую ветку в этой сессии.** У другого агента может быть назначена собственная ветка — ему нужно следовать правилам *его* среды, не слепо переключаться на эту.
2. Найди защищённый *игровой* вход с правами; зафиксируй URL, коммит и SHA-256. Проследи за loader **до реально доступного, допустимого тела**, но без запроса к запрещённому API и без обхода защиты. Если виден только loader/UI, сменяй кандидата.
3. Изучи подходящие офлайн-инструменты для версии защиты (Luraph 14/15, MoonVeil, MoonSec V3, IronBrew, Prometheus и др.), сначала проверь их исходники на исполнение/сеть. Если выход повреждён, попробуй иной безопасный метод. Не принимай декомпилятор нативного Luau за декодер пользовательского VM-байткода.
4. Проверь Lua синтаксис доступным компилятором и игровое поведение изолированными mock-тестами **только для восстановленных фрагментов**, сравнивая с разрешённым эталоном, где возможно. Не исполняй чужой top-level или Roblox без отдельного разрешения.
5. Публикуй подтверждённый код **только** в `dobf scripts 1.0/<точное название игры> ... .lua` с честным заголовком и статусом. Сделай новый отчёт с функциями/параметрами/ограничениями и JSON-манифестом (ориентир: [последний защищённый манифест](reports/game-sources-2026-10-21-protected.json)). При новом файле добавь манифест в `SOURCE_REPORTS` и необходимые проверки в [`scripts/verify_results.py`](scripts/verify_results.py): сейчас проверяется **точное соответствие содержимого каталога манифестам**. Обнови README/счётчики только после проверки. Если восстановление не доказано — отчитайся о причинах, **не повышай счётчик**.
6. Минимальные локальные проверки перед публикацией:

   ```bash
   python3 -m unittest discover -s tests -p 'test_*.py'
   python3 scripts/verify_results.py
   python3 scripts/verify_sources.py
   node --test tests/test_psu_fixed_calls.mjs
   git diff --check
   ```

   Профильные Lua/Node-тесты для изменённого результата смотри в `tests/` и старых отчётах. Не коммить сгенерированные образы, бинарники, `node_modules` или отсутствующие права.
7. Зафиксируй изменения в разрешённой рабочей ветке/PR и **обнови [reports/AI-HANDOFF.md](reports/AI-HANDOFF.md)**: что получилось, где код, проверки и какие подходы оказались тупиками. Следующий агент не должен принимать старый снимок за текущее состояние.

Если пользователь просто подключает другого ИИ, ему достаточно открыть репозиторий с GitHub-доступом и попросить: **«Прочитай `AGENTS.md` и `reports/AI-HANDOFF.md`, проверь текущий HEAD и продолжи работу по этим правилам»**. Никому не передавай GitHub-пароли или ключи Roblox в чате.
