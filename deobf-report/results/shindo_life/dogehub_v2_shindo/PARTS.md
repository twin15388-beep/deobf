# `dogehub_v2_shindo` — DogeHub V2 (Shindo Life), статический разбор

Тема: **shindo_life** · ScriptBlox 224947 · «Detected Key system» (badge, страница)
Источник: `NoobieDoge/DogeHubV2@Separated:ShindoLife` (44 639 B, скачано 2026-11-17)
Статус: **финальная версия восстановлена** (см. `RECOVERY.md`, 2026-11-17).
Ниже — исторический статический разбор контейнера; его вывод «финальный слой
недостижим» относится к офлайн-дешифровке 365 B-блока и остаётся верным
(блок в рантайме не используется — payload тянется по сети и является обычным Lua).

## Что доказано (измерено)

1. Внешний слой — плейнтекстовый Lua-VM (файл `work/sources/dogehub_shindo.lua`):
   `return (function(a,b)…end)("\\27\\76…")`, внутренняя инструкция-ассемблер
   Lua 5.1 (OpArg-таблица переупорядочена per-build — index 1 = `{OpArgK,OpArgN}`,
   не stock), 38 опкодов, форматы `ABC/ABx/AsBx`.
2. `payload.bin` (14 691 B) — **IronBrew** (`@Ironbrew/netcoreapp2.0/out.lua`),
   контейнер «почти stock luac 5.1», отличия от stock: прото хранит
   `Name=H(), FirstL=r(), LastL=r(), Upvals/Args/Vargs/Stack=s()` в заголовке
   прото; upvalue-секция после Const отсутствует; header-check `H(4)=="\27Lua"`,
   `s()==0x51`, `H(3)=="\4\8\0"`. Распарсен полностью (consumed 14691/14691).
   Парсер: `deobf-report/tools/ironbrew_dump.py` (в этом каталоге — dump.txt).
3. Внутри payload — тот же VM, портированный в IronBrew-байткод, плюс константа
   **K13** (570 байт, алфавит `0-9A-Z` без `F`). K13 декодируется
   base-35-подобным big-int алгоритмом из `main/1` (вложенный прото с константой
   36) в **365 B бинарного блоба** (`work/sources/dogehub_layer3.bin`).
4. 365 B НЕ являются raw IronBrew-ехема прото-дерева и не начинаются с luac-magic
   (XOR по одному байту к `\x1bLuaQ` не подходит) → это финальный
   мини-VM/зашифрованный блок, исполняемый `main/10` (497 инструкций,
   диспетчер по перечислениям ~257-276).
5. Косвенное доказательство ключ-системы: ScriptBlox показывает badge
   «Detected Key system» у DogeHub V2 — финальный код, скорее всего,
   подгружается по сети после успешной проверки ключа. Статически его нет.

## Что восстановлено полностью

- Формат IronBrew-контейнера и 100 % содержимого payload.bin:
  `dump.txt` (прото/константы/locals/upnames) + `disasm.txt` (полный дизасм
  всех 12 прото, стандартные имена опкодов 5.1, форматы по g[]/f[] из VM).
- Все строковые константы (верхнего слоя): `string,byte,char,sub,table,concat,
  math,ldexp,getfenv,setmetatable,select,unpack,tonumber,bit,bxor` + K13.
- Содержимое main-слоя: прото `main/0` (env-getter `_ENV`), `main/1`
  (base-35 декодер K13 + 256-элементная таблица-подстановка через
  `main/1/0`), `main/2` (эмуляция bxor через mod/div/pow), `main/3`
  (битовая эмуляция), `main/4` (чтение 4 байт LE → число),
  `main/5` (фабрика `r()`), `main/6` (декодер IEEE-double через ldexp-математику),
  `main/7` (читать строки), `main/8` (varargs `select('#',...)`),
  `main/9` (рекурсивный Reader прото-дерева), `main/10` (сам интерпретатор,
  497 инструкций).

## Чего НЕ восстановлено (честно)

- Исходный текст/байткод финального слоя (365 B): слои base-35-подобная
  дешифровка + мини-VM/ключ требуют реализации/эмуляции `main/1`…`main/10`
  целиком (оценка — несколько часов, риск высокой вероятности неверной
  эмуляции), либо законной выдачи ключа — не делаем.
- Поведение DogeHub V2 в рантайме не измерялось (скрипт не запускался).
